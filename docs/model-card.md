# DOXA model and system card

**Version:** application 0.6.0; each frozen analytical run retains its own methodology, rubric snapshots, model/provider identity and source selection. This is an orchestration and evidence system, not a newly trained foundation model. v0.6 adds low-memory execution, permissive PDF extraction, frozen measurement cards, explicit structural context, comparison/evaluation tools and recoverable native activities. Historical run methods and source text remain unchanged.

## Intended use

Research, civil-society monitoring, newsroom/policy analysis and teaching with declared frameworks and inspectable evidence. Use source-specific review to distinguish an author's position from quotation, reported allegations, counterspeech, hypothetical examples and descriptive framing. Rates describe a selected imported corpus.

The engine emits typed criterion outcomes, attribution and stance fields, exact source references and explicit unresolved work. Frameworks retain distinct definitions and boundary conditions. Political framing is descriptive; an observed frame alone establishes neither prejudice nor factual error. No demographic-persona simulation or private political-identity inference is needed.

## Model roles and provenance

The new [guided-pilot tools](managed-pilots-v05.md) use explicitly versioned deterministic rules for identifier previews and observable English wording. They do not establish calibrated tone, prejudice or emotion judgments. Optional detector interfaces do not install or execute a GLiNER model. The v0.5 guided-report examples and five practice texts are synthetic software demonstrations with no inference. The small v0.6 recorded starter preserves actual public-source model outputs and their original provenance, rather than generating new readings. Operator signatures do not establish qualifications or independent validation.

No model weights are downloaded during normal installation or software tests. DOXA has not fine-tuned these models.

## Evaluation status

The 5,000-source cloud run retained 204,342 of 204,421 explicit decisions and 4,927 complete source checks; 79 decisions remain unresolved. Exact-source audits measure anchoring and integrity. They do not measure semantic validity. Independent-model comparisons expose literal differences but do not establish which interpretation is correct.

The [independent evaluation scaffold](evaluation-v04.md) contains 200 cases with no fabricated human labels. Held-out cases require fresh, model-blind independent review before metrics are unlocked. The 120 functional fixtures are an authored protocol; their expected behaviors require rubric review and actual model execution. Interpretation accuracy, calibration and subgroup performance remain unmeasured.

## Measurement contracts and new evaluation controls

New service briefs freeze criterion method cards: an operational rule, construct, exact-context requirements, inclusion/exclusion rules, scholarly motivation and permitted report wording. [Measurement validity](https://arxiv.org/abs/1912.05511), [explicit framing annotation](https://aclanthology.org/P15-2072/), [behavioral testing](https://aclanthology.org/2020.acl-main.442/) and [human label variation](https://aclanthology.org/2022.emnlp-main.731/) inform those contracts. Their authors did not validate DOXA, and results from their tasks do not transfer automatically to this application's domains.

Reference tools now retain sampling/group/rights metadata, preregistration, per-criterion confusion tables, abstention, attribution, source-span concordance and reviewer agreement. Independent/cluster-aware confidence and release gates require their declared sampling assumptions, adequate review and a locked evaluation scope. A prepared panel, a self-attested probability sample, a completed annotation form or a computed diagnostic is not independent evidence by itself. The existing enriched 200-case pack remains diagnostic. The Company/Public/Personal panel collection target and its 40/20/40 split are a study protocol, not collected or annotated datasets.

Optional `structure-aware-1.0` context adds anchored headings, supplied mail ancestry and visible quotation markers. Context sufficiency remains review-required. New matching snapshots use declared event/topic/genre/date eligibility and disclose exclusions; they do not establish source independence, deliberate omission, fairness or causation. Prospective alert-review campaigns collect their own evidence using the existing trajectory engine. Shipping the campaign tooling does not establish a prospective false-alert rate.

The additional twelve context challenges are authored protocol proposals without executed model results or gold labels. The explicit functional runner does not fabricate results when it is not executed. Calibration, qualified human studies and real-artifact model-promotion evidence remain absent unless a separately identified receipt establishes them.

## Review and adaptation

Review records are appended separately from original model output. Approved examples can enter immutable memory snapshots; a candidate requires paired evaluation and explicit activation or rollback. Optional semantic overlays retain actor/version labels. The current system does not train weights or autonomously promote itself.

## Constraints

English-first methods and CPU profiles need separate multilingual validation. Missing context, extraction/OCR errors, ambiguous attribution, framework differences, source-selection bias and provider model changes can affect results. An omission or double-standard claim needs a declared relevant comparator. Keep source rights, reviewer authorship, incomplete coverage and plausible alternative readings with any downstream conclusion.

Deploy private workspaces with the authentication and data-transfer controls described in [deployment](deployment.md). Default attempt records contain metadata; historical visible prompts are not reconstructed as if they were actual captured requests.

## Local and hosted operating boundaries

The default local profile targets an 8 GB host. Docker limits the application container and child workers to 4 GiB; native Python only applies parser/worker controls. The browser, operating system and separate model server are outside that boundary. Whole-host usability on a physical 8 GB computer and contextual inference speed require separate measurements. No generative model is required for the packaged practice and recorded-reading workflows.

The [dedicated hosted-pilot recipe](hosted-pilots-v06.md) configures separate native installations, quotes, processing caps and backup/recovery controls. It has not established a live customer service, audited end-to-end data residency, subscriptions, shared customer tenancy or independent analytical quality. Automatic retention requires explicit installation and project opt-ins; it erases the whole project at the earliest raw/derived deadline measured from the latest policy save. Provider copies, backups and downloads remain separate obligations. See [privacy and recovery](privacy-lifecycle-v06.md) and [release verification](verification-v06.md).
