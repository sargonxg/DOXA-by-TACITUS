# v0.5 verification and release boundaries

v0.5 implements a native guided-pilot foundation around the existing evidence engine. This record distinguishes software verification from interpretation validity. No independent human labels, customer contracts, paid inference or commercial-readiness certification are produced by software tests.

## Implemented and exercised

- Company/Public/Personal briefs are validated, versioned and frozen into new runs. New profiled and managed analyses use local-only defaults until an allowed destination is explicitly configured. Existing unprofiled local workflows retain their documented consent behavior until a project policy is saved.
- Individual native credentials, signed HttpOnly sessions, explicit roles/project grants, revocation and server-attributed review identity. Managed access refuses remote persistence. Personal managed review uses its own personal installation.
- Endpoint classification uses the same resolver as actual adapters, including legacy environment aliases and explicit overrides. A loopback OpenAI-compatible cloud gateway remains remote unless local inference is explicitly declared.
- Pasted writing and bounded EML/MBOX extraction, exact Unicode anchors, message/quotation context and conservative author-count eligibility. Mail-normalized author rates are withheld pending suitable denominators.
- Rules-and-dictionary privacy previews, explicit transformed source versions, exact original/transformed mappings and authenticated AES-256-GCM identity maps. Original sources remain readable to authorized project users; no guaranteed anonymization is claimed.
- Policy checks before scheduling and inference reservations, export controls at generation/download, and worker-time access checks. Forged transformation metadata and edited transformed sources cannot bypass the registered-source requirement.
- Durable native whole-project erasure drains active API streams, synchronous endpoint threads, detached asynchronous worker threads, analysis/report leases and uploads. Ownership is registered before persistent writes, including failure-injected source/casebook/report outputs. Tests retain another project's records and shared artifacts.
- PDF/HTML/XLSX/JSON guided reports with exact evidence, human-readable charts, source/method hashes, separately attributed operator notes, corruption-checked downloads and explicit bounded appendices. Optional contextual findings require a matching frozen service brief and unchanged source metadata, retaining actual run/model/method and partial-processing coverage.
- Expanded independent annotation forms capture human-entered exact spans, targets/propositions, reporting chains, communicative acts and missing context without manufacturing reference labels.

## Validation performed

Local verification includes the complete Python regression suite, targeted cancellation/security/failure-injection tests, production frontend build/typecheck, and the real browser workflow in `tests/browser_pilot_v05.py`. The browser run covers all three profiles, selected-writing intake, estimates and exact wording evidence, policy enforcement, privacy transforms, generated report formats and an actual PDF download, erasure/receipt recovery, separate-project preservation, managed viewer login/logout and a 390-pixel viewport. It uses synthetic data, zero mocked routes and zero model requests.

The local integrated Python run passed **934 tests and six subtests** on Python 3.12. The [browser receipt](../benchmarks/v05-browser-smoke.json) records **11 real browser checks**, zero page errors, zero mocked HTTP routes and zero model requests. These counts measure software behavior on their stated fixtures; they do not measure interpretation accuracy.

TypeScript and **37 Workers emulator tests** passed. The self-contained 0.5.0 wheel installed into an empty directory and served its compiled UI, extracted TXT through the subprocess path, and produced a real XLSX through the report worker. Offline repository verification checked **412 local links and 80 artifact hashes**, with no failures or model requests.

The GitHub verification workflow runs Python 3.11/3.12/3.13, frontend build, Ruff/repository links and artifact hashes, Workers tests/typechecking, browser workflows, installed-wheel smoke tests and Docker health. See the [repository's actual Actions results](https://github.com/sargonxg/DOXA-by-TACITUS/actions). Release-specific completed run links and counts are recorded after the final checks; an available workflow is not itself a passed result.

The three [new example reports](pilot-reports-v05.md) are generated by a local script from published synthetic TXT inputs. Their manifests and [build receipt](../examples/v05-pilot-demo.receipt.json) retain actual hashes and record zero inference. A fabricated quotation is intentionally rejected. These examples demonstrate publication behavior, not model accuracy or real customer outcomes.

The earlier [5,000-source verification](verification-v04.md) remains a recorded v0.4 software/evidence baseline. Its original artifacts and partial results are retained. The new full-evidence release workflow uses fresh restored data and complete logical-table/object fingerprints; no original research workspace is upgraded or edited as part of those proofs.

## Migration and operating limits

Native schema 5 creates the pilot/privacy tables through an ordered migration with a checked pre-upgrade database backup. Stop old server processes and back up database **and objects** before upgrading. Applications supporting only schema 4 must not write an upgraded native workspace. The Cloudflare profile continues using schema 4 and its shared private-workspace contract; it is not managed multitenant SaaS.

Private provisioning and hardened erasure require POSIX. Erasure receipts cover inventoried live application records/artifacts and disclose that backups, provider retention, previously downloaded copies and physical-media wiping remain outside the operation. Unattributed historical artifacts fail closed for operator review. Retention targets currently create review candidates, not scheduled deletion.

Guided report rendering is synchronous and bounded: 100 sources, 2,000 blocks, 500,000 characters, 2,000 contextual decisions and 16 MiB per artifact. Existing persistent casebook/report jobs serve larger archives. Interactive privacy and wording previews have their own explicit selection/size limits. A passed 5,000-source replay does not establish 100,000- or million-source inference throughput.

The release does not implement real OAuth connectors, public signup/subscriptions, shared customer tenancy, audited endpoint residency or independently validated interpretation accuracy. Those remain gates in the [commercial roadmap](commercial-service-roadmap.md). [Operator setup](managed-pilots-v05.md) explains the actual configuration and limitations.
